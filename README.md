# 公考日报 · 每日时政与公考常识

一个给自己用的备考小站：**每天 10 条时政要闻 + 10 条公考常识**，逐条阅读、逐条背诵、可收藏、可导出、可离线。

页面是一份**零外部依赖的单文件应用**（`index.html`），双击就能打开，也能装到手机主屏当 App 用。内容通过 `data/` 目录下的数据文件注入，由 GitHub Actions **每天北京时间上午 8 点前后**自动更新并发布。

## 三、数据来源与获取方式（重点）

两类内容的性质完全不同，所以用了两套机制。

### 模块一：时政要闻 —— 自动抓取 + 人工校核

**⚠️ 先说结论：通用新闻源的自动抓取做不到「直接可用来备考」。**

实测过一次（`--source-check` + 真实抓取）：从中国新闻网滚动新闻抓 30 条候选，按规则筛完仍是这种画风 ——

> 「广西三江侗乡：梯田染金入画来」「浙江海宁：钱塘江滩涂现『潮汐树』景观」「河南许昌：胖东来客如潮」

这些是图片新闻和商业软文，对公考毫无价值。所以本项目采用的流程是 **自动抓取做初筛、人工用 5 分钟定稿**（和你现有日本电力期货站点「半自动更新」的做法一致）：

```
08:02  GitHub Actions 自动跑 scripts/fetch_daily.py
         ├─ 多源抓取（中新网 / 中国政府网 / 新华网 / 央视新闻…）
         ├─ 时政相关性打分（4 分门槛）→ 剔除非遗、风光、展会花絮等
         ├─ 时效过滤（默认丢弃超过 3 天的旧闻）
         ├─ 标题去重 + 自动分类打标
         └─ 写出 data/YYYY-MM-DD.js 并刷新 manifest
         ↓
      页面自动生效 ←—— 你随时可在本地用 data/manual/日期.json 覆盖/补充后提交
```

**已接入的数据源与实测体检结果**（2026-09-10 用 `--source-check` 实测）：

| 来源 | 地址 | 权重 | 实测状态 |
|---|---|---|---|
| 中国新闻网 | `www.chinanews.com.cn/rss/scroll-news.xml` | 10（一级） | ✅ **带时间戳，当日更新**，是唯一确认新鲜的源 |
| 中国政府网 · 要闻 | `www.gov.cn/yaowen/liebiao/` | 20 | ⚠️ 权威性最高，但本机网络下返回空页；在 Actions 环境通常可用 |
| 中国政府网 · 最新政策 | `www.gov.cn/zhengce/zuixin/` | 25 | ⚠️ 同上 |
| 新华网 · 时政 | `www.news.cn/politics/news_politics.xml` | 40 | ⚠️ 可用，但条目**无时间戳**，排序自动靠后 |
| 央视新闻 | `news.cctv.com/` | 50 | ⚠️ 可用，无时间戳 |
| 每日快讯 | `60s.viki.moe/v2/60s` | 90 | ⚠️ 仅作最后兜底填空 |
| ~~人民网 RSS~~ | ~~`people.com.cn/rss/politics.xml`~~ | — | ❌ **已长期停更**（最新条目停在 2025-06），已移除 |

> 这些地址随时可能变。你可以随时重新体检，按结果调整脚本里的 `SOURCES` 列表：
>
> ```bash
> python scripts/fetch_daily.py --source-check
> ```

**关键设计：宁可少发，也不拿社会新闻凑数。**
默认门槛 4 分、只放宽到 0 分，不为凑满 10 条而纳入明显无关内容。跑完如果不足 10 条，脚本会**大声警告**并提示你补录；页面也能正常显示少于 10 条。确实想强行凑满，加 `--fill`。

**人工兜底的优先级最高。** 建 `data/manual/2026-09-11.json`（照抄 `YYYY-MM-DD.json.example`），写进去的内容会被放在最前面，再用自动抓取补足到 10 条。抓取全挂时，只要这个文件在，当天就不会断更。

### 模块二：公考常识 —— 人工维护题库 + 自动轮换

常识是**稳定考点**，不会每天出现新知识，所以「每天更新」的正确做法不是去抓，而是**从固定题库里按周期轮换**。

- 题库在 `data/facts-pool.js`，当前 **100 条**，覆盖 7 大分类：
  政治 18 · 法律 18 · 经济 16 · 历史 16 · 科技 12 · 地理 10 · 人文 10
- 每条结构：`{ id, cat, q（考点问法）, a（答案要点）, tip（记忆提示 / 易错点）}`
- 页面按 `id` 记录「已背」，所以 **`id` 一旦确定就不要改**，否则历史记录会对不上
- 轮换算法：题库先按分类**交织**（保证每天的 10 条天然跨 4—7 个分类，单类最多 2 条），再以 10 条为一片、10 片为一轮顺序推进
  - ✅ 一轮之内**不重复**
  - ✅ 一轮 10 天**覆盖全部 100 条考点**
  - ✅ 跨轮顺序不同，避免死记「第几条是什么」
- **加题就是往 `items` 末尾追加**，不改代码也会自动纳入轮换。加到 200 条 → 一轮自动变 20 天

## 四、更新机制：每天上午八点是怎么实现的

```yaml
on:
  schedule:
    - cron: '2 8 * * *'        # 北京时间 08:02 —— 主更新
      timezone: 'Asia/Shanghai'
    - cron: '32 8 * * *'       # 北京时间 08:32 —— 兜底重试
      timezone: 'Asia/Shanghai'
```

**① 直接写北京时间，不用算 UTC。** GitHub 现已支持在 `cron` 旁加 `timezone` 字段（IANA 时区名），
所以不必再手工做 UTC+8 换算。历史上必须写 UTC，很多人的定时任务就是错在这里。

**② 刻意避开整点（写 08:02 而不是 08:00）。** GitHub 官方文档原文：

> The `schedule` event can be delayed during periods of high loads of GitHub Actions workflow runs.
> High load times include the start of every hour. If the load is sufficiently high enough,
> some queued jobs may be dropped.

也就是说整点是全球任务最拥挤的时刻，任务不仅会被延迟，**极端情况下会被直接丢弃**。
往后挪两分钟能显著降低这个风险。

**③ 兜底重试。** 脚本带 `--skip-if-fresh`：08:02 那次成功了，08:32 这次会直接跳过，不会重复抓取。

**④ 关于「60 天不活动会被自动停用」。** GitHub 官方规则是：公共仓库若 60 天内无任何仓库活动，
定时工作流会被自动禁用。本项目**天然免疫**——工作流每天都会把新一期数据提交回仓库，
这个提交本身就是仓库活动，计时器每天都在重置。万一将来真的停了（例如你连续两个月没动过仓库），
到仓库的 Actions 页面点一下 **Enable workflow** 即可恢复。
- 每次运行都会先跑**脚本自检**，再做**产出校验**（条数、必填字段、`manifest` 与磁盘文件一致性），任何一步失败都不会发布坏数据。
- **页面侧也会自检**：打开时会拉一次 `data/manifest.js`（`cache-control: no-store`），发现新一期就自动加载；切换回标签页时也会再查一次。若当天数据还没生成，页面顶部会出现黄色提示条和「立即检查更新」按钮。
- 想立刻手动更新：仓库 **Actions → 每日更新时政要闻 → Run workflow**，还能临时指定日期、强制重抓。

## 五、功能清单

**时政要闻**
- 10 条卡片：序号 · 分类标签 · 标题 · 摘要 · 来源
- 点卡片任意处即标记「已读」；右下角 ★ 收藏、✓ 打勾
- 「全部标记已读」、「复制今日时政」（Markdown 格式，可直接粘进笔记软件）

**公考常识**
- 每条含：分类徽章 · 考点问法 · 答案 · 记忆提示
- 默认**隐藏答案**：先看问题主动回忆，再点「看答案」核对（主动回忆是记得最牢的方式）
- 「展开 / 收起全部答案」一键切换；「复制今日常识」
- 展开答案即自动标记「已背」（可在设置里关掉）

**复习辅助（对应你提的附加需求）**
- **历史归档**：单独一个标签页，列出所有期数，点任意一期即可回看往期时政与常识；顶部日期选择器也能前后翻页，键盘 `←` `→` 同样可用
- **我的收藏**：跨天集中存放收藏的时政与常识，可导出为 Markdown
- **导出**：学习数据 JSON 备份（已读 / 已背 / 收藏 / 偏好）、当日内容 Markdown、全部内容 Markdown
- **导入**：选择此前导出的 JSON 恢复记录（覆盖前会二次确认）
- **进度统计**：顶部两条进度条实时显示当日完成度
- **离线 / 打印**：断网可用；`Ctrl+P` 打印时会自动隐藏导航和按钮，只留正文

**装到手机上**
- 手机浏览器打开线上地址，按下面步骤加到主屏，之后就像 App 一样全屏运行、可离线
- Android / Chrome：右上角 `⋮` → 「添加到主屏幕」
- iPhone / iPad：**必须用 Safari** → 底部「分享」→ 「添加到主屏幕」（微信内置浏览器不支持）
- 电脑 Chrome / Edge：地址栏右侧出现「安装」图标，点击即可独立窗口运行
- 小屏下顶部标签会自动切换成两字简称（时政 / 常识 / 收藏 / 归档 / 设置），保证五个标签一屏放下

## 六、部署到 GitHub Pages（每天上午 8 点自动更新）

本地仓库**已初始化并完成首次提交**，远程也配好了（`origin` → `git@github.com:Heart-ws/gongkao-daily.git`），
所以只剩两步。

**第 1 步：在浏览器里创建一个空仓库**

打开 <https://github.com/new?name=gongkao-daily&visibility=public>

- Repository name 填 `gongkao-daily`
- 选 **Public**（私有仓库用 Pages 需要付费版）
- ⚠️ **不要**勾选 "Add a README file" / ".gitignore" / "license" —— 必须是完全空的仓库，否则推送会冲突

**第 2 步：推送**

```bash
bash scripts/push_to_github.sh
```

脚本会自己检查 SSH 通不通、远程仓库存不存在，再推送并打印站点地址。
换过仓库名就加个参数：`bash scripts/push_to_github.sh 你的仓库名`

**第 3 步：开启 GitHub Pages（只需做一次）**

推上去后第一次运行会在「配置 Pages」这步失败，这是**预期内的**——不要慌。

打开 <https://github.com/Heart-ws/gongkao-daily/settings/pages>

- **Build and deployment → Source** 选 **`GitHub Actions`**（不要选 Deploy from a branch）
- 点 **Save**

> **为什么这一步不能自动化？** 创建 Pages 站点属于「仓库管理」级操作。
> GitHub 出于安全考虑，让 Actions 自带的 `GITHUB_TOKEN` **永远**没有这个权限——
> 与工作流里 `permissions:` 怎么写无关。所以 `configure-pages` 的 `enablement: true`
> 在普通仓库里必然失败。**只有用个人访问令牌（PAT）或 GitHub App 令牌才能自动化**，
> 为这一个动作去配 PAT 不值得。手动开一次，之后永久生效。

**第 4 步：重新跑一次工作流**

开启 Pages 后，回到 <https://github.com/Heart-ws/gongkao-daily/actions>，
打开那条失败的运行记录，点右上角 **Re-run all jobs**。

约 1—2 分钟后就完事了：

1. 站点地址：`https://heart-ws.github.io/gongkao-daily/`
2. 之后每天**北京时间上午 8 点**自动抓取并更新（08:02 主更新 + 08:32 兜底重试）
3. 以后你改了页面推送上去，也会立刻自动重新部署

> ⚠️ 如果仓库设为 **Private**，GitHub Pages 需要付费版才能公开发布。备考自用直接建 **Public**。

### 与已有站点的部署方式对比

你原来的 `japan-power-futures` 走的是「Actions 抓取 → 提交 → **Netlify** 部署」。
本站改用 **GitHub Pages**：不需要第三个账号，Pages 也能由 Actions 直接发布。
两者共同点是「云端 Runner 独立运行、无需本机开机、无需任何密钥」。

## 七、日常维护手册

**Q：改了内容后，怎么更新手机上的那一份？**

改完 `index.html` 或 `data/` 之后重新打包发布一次即可：

```bash
python scripts/build_dist.py     # 只把线上需要的 12 个文件拷进 dist/
```

然后把 `dist/` 目录重新发布一次。如果用的是 GitHub Pages，直接 `git push` 就行，Actions 会自动接管。
`build_dist.py` 会顺手做两项校验：`index.html` 里不能残留任何 http 外链、`manifest.js` 里列的日期必须在磁盘上真实存在，任一条不满足就直接报错退出，避免把坏版本发出去。

**Q：想加公考常识题？**
打开 `data/facts-pool.js`，在 `items` 数组末尾追加，遵循原格式即可。`id` 取个不重复的（如 `fl19`、`jj17`），改完刷新页面就生效。

**Q：想改某天的时政内容？**
新建 `data/manual/2026-09-11.json`（照抄同目录下的 `.example` 模板），填好标题和摘要，然后：

```bash
python scripts/fetch_daily.py --date 2026-09-11
```

你写的内容会排在最前面，自动抓取的只用来补足剩余条数。

**Q：抓取的内容质量不行 / 报错了？**

```bash
python scripts/fetch_daily.py --source-check          # 体检各源
python scripts/fetch_daily.py --date 2026-09-11 --fill # 强行凑满 10 条
python scripts/fetch_daily.py --offline --date ...     # 完全离线，只用人工文件
```

**Q：想自己跑一遍全部测试？**

```bash
node _dev/_test.js                              # 前端逻辑，76 项断言
python scripts/fetch_daily.py --selftest        # 抓取脚本，32 项断言
python _dev/_validate.py                        # 产出校验
```

**Q：想换图标？**
改 `scripts/make_icons.py` 里的配色常量，然后 `python scripts/make_icons.py` 重新生成四件套。纯标准库实现，不需要装 Pillow。

## 八、已知限制与注意事项

1. **自动抓取的时政质量有天花板**。再好的关键词规则也无法把「商业软文」和「重要时政」完全分开。当前默认「宁缺毋滥」（不够 10 条就少发 + 告警）。如果你希望每天稳定出满 10 条**高质量**内容，最可靠的做法是接一个商业新闻 API，或坚持「自动抓 + 人工 5 分钟定稿」。
2. **学习数据只存在本机浏览器**（localStorage）。换设备、清理浏览器数据、用无痕模式都会丢，建议每周在设置页导出一次 JSON 备份。
3. **没有任何外部依赖**，所以 `index.html` 双击就能用；这也意味着页面上不能引 CDN 字体或第三方图表库。字体走系统字体栈。
4. 首次打开需要联网拉取数据文件；之后 Service Worker 会缓存，断网也能看已加载过的内容。
5. 时政内容版权归原作者与发布机构所有，本页仅作个人学习备考整理，请勿对外分发。
6. `_dev/` 与 `data/manual/` 里的示例文件不参与线上运行，但都保留着，方便你日后照着改。

## 九、内容准确性说明

`data/2026-09-08.js` ~ `2026-09-10.js` 这三期是**人工校核稿**，作为内容质量的参照基准 —— 每条都核对过来源、重写过摘要、剔除了社会新闻。工作流产出的则是自动初筛稿，质量会低于这个基准。

常识题库的 100 条考点按现行法律与政策口径编写（如民法典 2021 年施行、刑法修正案十一的追诉年龄、2026 年是长征胜利 90 周年等）。政策与数据会随时间修订，**正式应考前请以官方最新发布的文本为准**。
